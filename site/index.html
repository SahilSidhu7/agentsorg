Where the tokens don't go.

Most of an agent's bill is overhead it never needed. agents.org cuts it before the first word of the task.

A tiny system promptEach call replaces Claude Code's large default prompt with a few lines about the employee's role. A test call costs about 600 tokens.
Less hidden thinkingHaiku spent about 70% of its output on thinking you never see. It now runs at low effort: output tokens fell 42% in our tests, and the answers stayed the same length.
A map, not a searchDepartments that edit files get a map of their folder up front, so they don't spend turns listing and reading just to orient. A real coding task used 34% fewer new tokens.
No tools unless neededWriters and analysts run text-only, with no tool schemas. Only Engineering gets file tools, fenced into its own folder.
Nothing of yours leaks inYour CLAUDE.md, hooks, plugins, MCP servers and skills aren't loaded into agent calls.
Knowledge by retrievalThe shared knowledge base is searched per task and only the top three snippets go in, never the whole thing.
Answers you already paid forThe same task within 24 hours comes back from cache at zero tokens.
Idle is freeNothing runs between your commands except schedules you made yourself. Walking around the office is just animation.

Point it at your project. Get a company.

It reads your project once, including your CLAUDE.md rules, and every agent starts from that instead of exploring. Then you give commands and review results.

  • It learns the project firstThe file tree, CLAUDE.md and AGENTS.md rules, README, manifests, CI config and recent commits go into one context pack. Secret files are never opened. It re-reads only what changed, at most once a day.
  • Free routing, one plan"@sales …" or a one-team request goes straight there for 0 tokens. Bigger work gets one planning call on Sonnet that knows your goals and past decisions.
  • One result per commandTeams hand work over by summary and file, and you get one combined result checked against what you asked. Accept merges any code; redo sends it back with your note.
  • Five things at most"Needs you" holds results, drafts to send, questions and problems, five at a time. A result you never open closes after a week, so nothing piles up.
  • Asked once, never againTeams decide ordinary things themselves. Only what's truly yours (a price, money, access, publishing) comes to you as one question, and your answer is kept for good.
  • Built to be left runningNothing runs twice or gets stuck, errors never move up to pricier models, agents can't read your keys or credentials, files are written safely, and the database is backed up daily.

Win clients, not just tasks.

The company keeps the record a founder needs: who you're talking to, what was said, what they paid. Agents add what they find; you decide what goes out.

  • ClientsLead, contacted, replied, qualified, proposal, won. Every email, note and payment on one page; reply rate, customers and revenue counted from it, not typed.
  • An outbox you controlAgents draft; you edit and click Send once you've added a mail key, or send it yourself and mark it sent. Nothing goes out on its own.
  • An activity logWhat you asked, how it was understood, what each team delivered and what it cost. Nothing happens off the record.
  • Goals and your own schedulesEvery agent works toward your goals. "Every Monday at 9, review the pipeline" runs only because you set it up.
  • Abilities per teamSwitch on file editing, web research or a shell, one team at a time. Text-only teams stay the cheapest.
  • Keys and tokensGive agents API keys without showing them the values. Keys stay on your machine, never enter a prompt, and are masked if an agent repeats one.

Small on purpose.

An earlier version tried to run the company by itself: weekly plans, agents deciding for you, meetings, follow-ups. On a real startup it made noise and spent the plan. 0.8 keeps what a founder actually used.

  • Nothing runs you didn't ask forNo background plans, no self-started follow-ups. Only your commands, and schedules you made.
  • Four placesToday, Clients, Outbox, Company. Everything else sits under Company.
  • Gate the irreversible, not the workSending, merging, keys and spending wait for your click. Planning and doing don't.
# what 0.8 removed
  weekly self-made plans
  research deciding for you
  agent follow-ups and side questions
  the conference room
  plan approvals, proposed teams
  inbound mail, reports, mods
# what stayed
  one command → one result
  clients · outbox · activity log

Or paste one prompt into Claude Code.

Open Claude Code in your project and paste this. It installs agentsorg, reads your project, asks you the few questions the design needs, and asks before setting up anything that runs in the background. It shows you each command first, and it won't touch your files unless you say so.

Setup promptPlain text
Set up agents.org for this project. It's a small company of Claude agents for a founder that runs on my Claude Code subscription (docs: https://agentsorg.sahilsidhu.pro).

Show me each command before you run it, and follow these steps:

1. Check that Python 3.11+ and the `claude` CLI are available. If Python is missing or older, stop and tell me how to install it.

2. Install agentsorg with the installer for this OS:
   - macOS / Linux: curl -fsSL https://agentsorg.sahilsidhu.pro/install.sh | sh
   - Windows (PowerShell): irm https://agentsorg.sahilsidhu.pro/install.ps1 | iex
   If `agentsorg` isn't found afterwards, open a new terminal, or call it by its full path: ~/.local/bin/agentsorg (Windows: %LOCALAPPDATA%\agentsorg\bin\agentsorg.cmd).

3. Understand the startup:
   - Read this project's README, manifests (package.json, pyproject.toml, go.mod and so on) and folder structure. Don't open secrets, .env files or credentials.
   - Write a 2-4 sentence description: what the product is, who pays for it, and the work it needs now (code, content, sales, research...).

4. Create the company around this project:
   agentsorg init ~/<project-name>-office --project "<absolute path of this project>" --describe "<description>"
   --project links this folder live and read-only and reads it once into a context pack every agent starts from (never secret files). The designer may ask up to 4 short questions (customer, offer and price, stage, 90-day target): ask me each one and use my answers; "not decided" is a fine answer for the price. It proposes 2-5 teams and up to 3 goals. Show me all of it before I approve.
   From now on, add `--company <project-name>-office` to every agentsorg command, or run them from inside that folder.
   If the design step fails because Claude isn't logged in, tell me to run `claude` and type /login, then run `agentsorg --company <project-name>-office design "<description>"`.

5. Run `agentsorg check` and tell me what it reports.

6. Ask me before running `agentsorg service install`. It keeps the company running in the background and starts it at login.

7. Finish with a short summary: the company's name and folder, how to open the dashboard (`agentsorg start`, or `agentsorg info` for the link if the service is running), and how I'll work with it: Today (give one command, see what needs me), Clients, Outbox (nothing is sent without my click) and Company. Useful commands: `agentsorg ceo "<command>"`, `agentsorg projects`, `agentsorg clients`, `agentsorg log`, `agentsorg env` (API keys for agents).

Don't add schedules, switch on web or shell abilities, add keys, or change files in this project unless I ask.
